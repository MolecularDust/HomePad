# HomePad for macOS

A Windows–style launcher for macOS, built as a Swift Package. A global shortcut (default
Option-Space) pops up a centered panel with a search bar (backed by the Spotlight index) above a grid
of pinned apps. The grid is meant to replace the Dock: apps live in user-defined categories (Essentials first, seeded from the
Dock on first launch, plus custom ones), with a read-only Running section. See [README.md](README.md) for user-facing behavior.

## Technical facts

- Targets **macOS 13+** (`Package.swift`: `.macOS(.v13)`, swift-tools-version 5.9). Pure SwiftUI + AppKit, no dependencies.
- Runs as a menu-bar app with **`LSUIElement`** (no Dock icon; `main.swift` also sets `.accessory` activation policy).
- **Unsandboxed.** It reads the Dock's prefs, runs `defaults`/`killall Dock`, and searches the whole index, which a sandbox would block.
- Distributed **outside the App Store**; `build_app.sh` ad-hoc signs (`codesign --sign -`), so first launch may need right-click → Open.
- Global shortcut uses Carbon **`RegisterEventHotKey`** (no Accessibility permission needed).
- Search uses **`NSMetadataQuery`** (Spotlight index), debounced 80 ms, scope `NSMetadataQueryLocalComputerScope`.
- Initial pinned list comes from the Dock's **`com.apple.dock` `persistent-apps`** preference (via `CFPreferences`), Finder prepended.
- "Hide the Dock" sets `autohide` + `autohide-delay=1000` in `com.apple.dock` and restarts the Dock.
- Launch at login via `SMAppService.mainApp`. Settings are stored in `UserDefaults` (`categories`, `columns`, `showRunning`, `hotkey*`, `doubleTapKey`, `hotCorners` as "topLeft,bottomRight", `folders` as JSON, `hideMinimised` (default true)). Bundle id is `local.mike.HomePad`.
- Permissions (prompted at runtime): Screen Recording (window thumbnails), Accessibility (raise or close a specific window, double-tap trigger), Full Disk Access (no API to request it; without it NSMetadataQuery silently omits files in Documents, Desktop and Downloads). Ad-hoc signing means macOS may re-ask after a rebuild.

## Layout

| File (`Sources/HomePad/`) | What it does |
|---|---|
| `main.swift`, `AppDelegate.swift` | App startup, menu-bar icon, settings window |
| `Trigger.swift` | Double-tap-modifier trigger (global `NSEvent` monitor), `LegacyMigration` from the earlier bundle ids `local.mike.SpotlightPlus` and `local.mike.StartMenu` |
| `HotCorners.swift` | `HotCorner` (frame in a corner, macOS's own `wvous-*` corner action for the clash warning) and `HotCornerMonitor`: polls `NSEvent.mouseLocation` at 20 Hz only while a corner is chosen (no permission needed), 0.2 s dwell, re-arms after leaving by 40 pt, ignores drags; opens the panel in that corner |
| `Folders.swift` | Windows-style folders: `FolderPopup` (the open folder over the tiles; a tile dragged out of its card closes it), `MergeTarget` (the tile a drop would merge with), `MiddleHover` (merging waits for a 0.5 s rest on a tile's icon), `EdgeHover` (reorder waits 0.12 s over a tile's edge, and after a reorder the pointer must move 12 pt before the next, which stops tiles swapping back and forth), `FolderIcon` (2×2 minis), the popup card and its drop delegate. Data: `Folder` / `FolderRef` / `Container` in Model.swift; a folder sits in a category's `paths` as "homepad-folder:<id>", saved under `folders`; one item left → it becomes that item (held off during a drag, `holdsFolders`) |
| `ShortcutConflict.swift` | Detects who else uses the global shortcut (macOS shortcuts exactly, known launcher apps as a guess) and shows the explanation dialog; Carbon registration does NOT fail on clashes |
| `Onboarding.swift` | First-run welcome window (permissions + shortcut); reopen via menu bar → Setup Guide… |
| `FilePicker.swift` | "Add File or Folder": our own file browser window (sidebar, grid, back, hidden-items toggle) with a Trash entry; `~/.Trash` is hidden so the system open dialog never shows it |
| `Dialogs.swift` | `ModalWindow` (titled, closable, runs via `NSApp.runModal`), `TextPrompt`, `AppPicker`; replaces NSAlert/NSOpenPanel so dialogs have a close button |
| `Spaces.swift` | Private SkyLight calls, looked up with `dlsym`: which Space a window is on (hidden helper windows are on none), bringing a window forward, and `RemoteAX` (Accessibility elements for windows on other Spaces, found by scanning element ids; windows sit at ids in the thousands). OK because the app is unsandboxed and not on the App Store |
| `Windows.swift` | Permissions, window thumbnails (ScreenCaptureKit; needs macOS 14 for images), hover popup panel, jump to window via Accessibility, `MinimisedWindows` (each running app's minimised windows with thumbnails, gathered in the background on every panel open; shown after the app's tile in Running as `MinimisedTile`) |
| `HotKey.swift` | Global shortcut (Carbon `RegisterEventHotKey`), `Shortcut` model + persistence |
| `Panel.swift` | The centered floating `NSPanel` and its keyboard handling |
| `HomePadView.swift` | The UI: search bar, category grids, placeholder tiles, running apps, results list. The blank space below the last section is padded onto that section (`fill`, worked out in `HomeView.updateFill` from the last row's measured frame and the viewport height), so its right-click menu and window drag cover it; the generic "Add … to Essentials" menu is left only for when there are no rows. A category's menu has Sort Alphabetically (`CategoryStore.sortAlphabetically`, same-named items keep their order; folders sort by their names) |
| `Calculator.swift` | Arithmetic typed in the search field (hand-written parser, not NSExpression, which throws on bad input); result card appears first |
| `Search.swift` | Spotlight-index search via `NSMetadataQuery` |
| `Model.swift` | Dock import, `CategoryStore` (categories, persisted as JSON), running apps, launching, Dock hiding |
| `SettingsView.swift` | Settings in toolbar tabs (`SettingsTabs`, an `NSTabViewController` with `.toolbar` style; one SwiftUI form per `SettingsTab`: General, Mode, Taskbar, Opening, Panel, Permissions). The window takes each tab's height, top edge kept, and reopens on the last tab (`settingsTab`); the Taskbar tab is always there, grayed out with a Use Taskbar Mode button in other modes. Also the shortcut recorder |
| `Localization.swift` | Languages (`codes`: English plus 19 `.lproj` folders) and the choice (Settings → General, menu-bar menu → Language), listed by macOS's own language names. HomePad keeps running in the Mac's language, so macOS hands it app, folder and file names as the Mac shows them; only HomePad's own text is in the chosen language (stored as `language`): SwiftUI windows get it as their locale via `.localized()`, Strings come from `L("…")`. A macOS name inside a text is written `⟦Trash⟧` and filled in from macOS's own language (Finder's), alone it is `Mac("…")`. The layout direction is forced with `AppleTextDirection`/`NSForceRightToLeftWritingDirection`, since AppKit takes it from the Mac's language. Choosing restarts via `Relaunch`. The Essentials category is renamed to the current language while it still has a default name |
| `DockIcon.swift` | HomePad + Dock mode (`DockIcon.isOn`): finds HomePad's own icon among the Dock's Accessibility elements (`AXURL` = the running bundle's path; needs Accessibility), the Dock's side from `com.apple.dock` `orientation`, and whether HomePad is in `persistent-apps` (so a copy run from another folder isn't "in the Dock"). `PanelController.show` places the panel by it (not for hot corners); a Dock click arrives as `applicationShouldHandleReopen`, and one within 0.3 s of the panel closing counts as "close" |
| `Modes.swift` | `HomePadMode` (Settings → Mode, stored as `mode`): `standalone`, `dock` (`DockControl.showWithHomePad` turns off any auto-hide and adds HomePad to `persistent-apps`), `taskbar` (`DockControl.hideForTaskbar`, which also puts back the Dock size, magnification and side an earlier version changed, saved under `dockBeforeTaskbar`; `Taskbar` shown; the Running section leaves the panel). Standalone hides the Dock too; each switch sets the Dock again, whatever it was. `DockControl` asks the Dock itself whether it auto-hides (`CoreDockGetAutoHideEnabled`; its preferences can lag), runs changes one at a time on a serial queue and posts `DockControl.changed` when one is done. `startButtonOnly` turns off the shortcut, double-tap and hot corners in taskbar mode (`globalTriggersAllowed`). `migrate()` turns the old `panelAboveDockIcon` switch into `dock` |
| `TaskbarTray.swift` | The taskbar's right end: `NetworkStatus` (NWPathMonitor, Wi-Fi signal from CoreWLAN, which needs no Location permission; only the name would), `VolumeStatus` (CoreAudio default output, polled every second; `VolumeScroll` changes it by 1/16 per scroll step over the icon), `BatteryStatus` (IOKit power sources), the clock (`TimelineView(.everyMinute)`, the Mac's formats), and `TaskbarFlyout` pop-ups (volume slider, calendar) that close on any click elsewhere. Switches `taskbarShows{Network,Volume,Battery,Clock}`. Network and battery open System Settings pages: on macOS 27 the menu-bar status items belong to `MenuBarAgent` and expose no names or actions, so their menus can't be opened |
| `WindowFitter.swift` | Taskbar mode: AXObservers on every regular app (window created / resized) shorten a standard window that reaches under the taskbar, or move it up if it would get under 200 pt; waits for the mouse button to be up; skips full-screen and minimized windows, and windows only moved; fits all windows when the taskbar appears. Needed because the real Dock can't sit under the taskbar to reserve the space: it shows its name labels wherever the pointer passes over its icons |
| `Taskbar.swift` | Taskbar mode's bar: a borderless nonactivating `NSPanel` one level above ordinary windows (so other apps' floating overlays, such as Gemini's dictation bar, come over it) along the bottom of the main screen (never key, takes the first click), Auto-hide (`taskbarAutoHide`): `Taskbar` polls the pointer at 20 Hz while it's on, slides the panel just below the screen (`frame` stays where it comes back to, so the panel and pop-ups position by it), reveals it after the pointer has rested on the bottom edge for `taskbarRevealDelay` ms (Settings, 0–1000, 300 by default) (not within 12 pt of a chosen bottom hot corner), and hides it 0.4 s after the pointer leaves unless `keepsUp` (HomePad's panel, a pop-up, a window preview, a drag, or the run loop in `.eventTracking` mode, which a menu uses); `WindowFitter` stands down while it's on and `refit()`s when it's switched. Start button, then `Taskbar.items()`: `TaskbarPins` (paths under `taskbarPins`, its own list, apart from the categories) and the running apps, ordered by `RunningOrder.taskbar` (`taskbarOrder`). Hover shows `WindowPreviewController` above the icon (`screenTile`); right-click is `AppTileMenu(onTaskbar:)` (Pin/Unpin Taskbar, and Pin to / Unpin from HomePad for the categories), the blank space `TaskbarMenu` (Add App…/Add File or Folder… through `PinTarget.taskbar`, which the pickers take); running apps switched off in Settings → Mode → Running apps (`TaskbarAppsList`) or with Hide from Taskbar leave it (`TaskbarShown`, paths under `taskbarExcluded`; pinned items always show); the active mark compares app paths (`FrontmostApp.path`), since an app can run as several processes; `TaskbarLabel` is its own name label (Start button, items without a window preview), since macOS shows tooltips only for the app in front; `TaskbarHighlight` is the pale square behind a pointed-at or front icon. `Taskbar.Alignment` (`taskbarIconsAlignment`, `taskbarStartAlignment`: centre or left/leading; HomePad's icon is left whenever the app icons are, `Taskbar.startIsLeft`, and the panel then opens at the leading edge above the taskbar). `TaskbarFileDrop` / `TaskbarFileDropDelegate`: apps, files and folders dropped on the taskbar (Finder's file URLs, or a panel tile through `PanelState.draggingItem`, whose own drag then ends with the tile back in place) are pinned before the icon let go on (`TaskbarPins.pin(_:before:)`); no slot opens up meanwhile (neither Windows nor the Dock show one). `TaskbarDrag` reorders as an icon passes over another (RunningDrag's private type), ending when the mouse button is up. `Launcher.hide` hides every process of the app through Accessibility and asks each too (logged under category `hide`), since `NSRunningApplication.hide()` may be ignored from an app that isn't in front |
| `RunningOrder.swift` | Reordering in the Running section: `RunningOrder` (saved order of app paths under `runningOrder`; unplaced apps go last, alphabetically; a quit app keeps its place; `sortAlphabetically()` clears it, from Running's right-click menu), `RunningDrag` (the tile in the air, drawn as `DashedSlot` by `AppTile` when `categoryID == nil`; Esc or a drop elsewhere restores the order from before the drag), `RunningDropDelegate` (reorders after `EdgeHover` settles, like pinned tiles). Its own item type, `local.mike.homepad.running-tile` (declared in the Info.plist by `build_app.sh`, `.ownProcess` visibility), so categories, other apps and the desktop can't take a Running tile. It hooks into `PanelState.beginDrag`'s timer (Esc, end of drag). Debug build: `-HomePadRunningOrderTest YES` runs a self-test of the ordering |
| `Snapshot.swift` | Debug builds only: `-HomePadSnapshotDir` draws the windows to PNGs and quits (`tools/snapshot.sh <code>`; `settings-<tab>` is each Settings tab as its window shows it, `full-<tab>` the same tab at full height), no screen permission needed |

`activateSelf()` uses `NSApp.activate(ignoringOtherApps:)` on purpose: the cooperative `NSApp.activate()` is often refused on macOS 14+, and then the panel opens without keyboard focus.

Pop-ups must go through `PanelController.keepVisible` so the panel stays visible behind them.

Localization is described in full, for reuse in other projects, in [LOCALIZATION.md](LOCALIZATION.md).

All user-facing text is translated: SwiftUI's `Text("…")`/`Button("…")` literals follow the window's locale
(`.localized()` on every hosting view's root); text passed as a `String` (AppKit menus and alerts, our own views'
titles) must be `L("…")`, with interpolation for values (whole sentences, never glued pieces). Never translate what
macOS names (apps, folders, files, System Settings and its sections, Mission Control, the Dock…): write it `⟦Name⟧` in
the English text (and use `L`, also for a SwiftUI text), or `Mac("Name")` alone. The English is the key. Translations
live in `tools/translations/<code>.json`; `tools/localize.py check` (finds the texts via the compiler's
`-emit-localized-strings`, plus each ⟦name⟧) reports missing ones and ones whose placeholders or ⟦names⟧ don't match,
`write` regenerates `Resources/*.lproj/Localizable.strings` and `InfoPlist.strings`. Translated text runs longer than English, so captions
need `.fixedSize(horizontal: false, vertical: true)` and button rows must be able to wrap.

Other top-level files: `Package.swift`, `build_app.sh` (`UNIVERSAL=1` for arm64 + x86_64), `README.md`, `INSTALL.md` (install guide for friends; keep it in step with the Setup Guide and Settings wording). `tools/make_release.sh` zips the universal app with `INSTALL.md` into `dist/HomePad.zip`, `tools/make_dmg.sh` makes `dist/HomePad.dmg` (app, Applications shortcut, `INSTALL.md` as plain text), and `tools/make_pkg.sh` makes `dist/HomePad.pkg`, an unsigned installer wizard whose pages are `tools/pkg/resources/*.html` (keep them in step with the Setup Guide), with `preinstall` (quit a running HomePad) and `postinstall` (open it for the logged-in user) in `tools/pkg/scripts`; the component is not relocatable, so it always lands in /Applications. `tools/make_installer_dmg.sh [code|all]` puts that package in `dist/HomePad-Installer.dmg` (English; other languages `dist/<code>/HomePad-Installer.dmg`, same file name for the Trash check) whose window background (`tools/render_dmg_background.swift`, 660 pt wide, its height and the two icons' positions measured from the text, which it hands back to the script; bottom 70 pt left empty for Finder's tab and status bars; mirrored for Arabic and Persian) shows the Open Anyway steps top to bottom in one card, with the installer (given the classic package-box icon from Installer.app; newer macOS draws packages blue) under step 1 and a blue Open Privacy & Security tile under step 3: a Finder alias named "Open System Settings" to `/System/Library/PreferencePanes/Security.prefPane` whose icon is that square tile (`tools/render_dmg_icons.swift`), at the installer's 112 pt icon size. Square on purpose: Finder highlights an item's whole icon square and its name on a click (no way to turn that off), so a wide button got a big grey box over the text. All installer text (pages, the disk image's picture, tile and file names) is in `tools/pkg/text/<code>.json`; `tools/pkg/make_pages.py` builds the pages per language (Installer shows the Mac's language; it has no language menu of its own) and `--check` compares them with English. macOS's own buttons and names there are the official ones of that language, and English for Bengali, Telugu, Filipino and Persian, which macOS isn't available in. Installer's own offer to move the disk image to the Trash at the end fails only when an earlier `HomePad-Installer.dmg` that the user trashed in Finder is there (Installer may replace its own earlier copy, not another app's); the last page says it's harmless. A warning up front can't tell the two apart, so there is none. Installer turns its HTML pages into plain styled text, so `tools/pkg/resources/style.css` keeps to fonts, margins and lists (no positioning or rounded badges; right-to-left lists get their numbers written in, since Installer puts list numbers on the left); it lays the window out through Finder AppleScript, so it needs Automation access to Finder and briefly opens a window. `pkgbuild` prints "write: Permission denied" in Claude's shell; harmless. `dist/` is git-ignored. `Resources/uninstall.sh` is copied into the app by `build_app.sh`; the menu-bar menu's Uninstall HomePad… brings the Dock back and unregisters launch at login in-app, then runs a temp copy of it with `--wait <pid> --notify <app path>` and quits (it has `--dry-run`; never run it for real on the development Mac). The app icon is `Resources/AppIcon.svg`; `tools/make_icon.sh` renders it into `Resources/AppIcon.icns`, which `build_app.sh` copies into the bundle (`CFBundleIconFile`).

## Build

```
./build_app.sh      # release build + assembles "build/HomePad.app" (Info.plist, ad-hoc codesign)
swift build         # compile only (debug)
```

`build_app.sh` stamps the real SDK version into the binary (`-platform_version macos 13.0 <sdk>`); SwiftPM alone records SDK 13.0, which makes macOS draw the app in an older compatibility look (small traffic lights). Check with `otool -l ... | grep -A4 LC_BUILD_VERSION`.

Output is `build/HomePad.app`; `.build/` and `build/` are git-ignored. To work in Xcode, open `Package.swift`.
